# 雲端同步設定（Supabase，免費方案即可）

遊戲用信箱驗證碼登入，進度存在你自己的 Supabase 專案裡。程式碼在 `js/cloud.js`，專案設定在 `js/cloud-config.js`。只需要設定一次。

## 1. 建立專案

1. 到 <https://supabase.com> 註冊並登入，按 **New project**，名稱隨意，地區選 **Northeast Asia (Tokyo)** 或 Singapore，資料庫密碼自己記下（遊戲用不到）。
2. 建好後到 **Project Settings → API**（或首頁的 Connect／API Keys），記下：
   - **Project URL**：`https://xxxx.supabase.co`
   - **anon public key**（新版介面叫 **publishable key**，`sb_publishable_…`）
   - ⚠️ 不要用 `service_role`／`secret` key。

## 2. 建立資料表

左側 **SQL Editor → New query**，貼上以下內容並按 **Run**：

```sql
create table if not exists public.saves (
  user_id    uuid not null default auth.uid() references auth.users(id) on delete cascade,
  project    text not null,
  rev        bigint not null default 1,
  data       jsonb not null,
  device     text,
  updated_at timestamptz not null default now(),
  primary key (user_id, project)
);

alter table public.saves enable row level security;

create policy "saves_select_own" on public.saves for select to authenticated using (auth.uid() = user_id);
create policy "saves_insert_own" on public.saves for insert to authenticated with check (auth.uid() = user_id);
create policy "saves_update_own" on public.saves for update to authenticated using (auth.uid() = user_id) with check (auth.uid() = user_id);
create policy "saves_delete_own" on public.saves for delete to authenticated using (auth.uid() = user_id);

grant select, insert, update, delete on public.saves to authenticated;
```

RLS 確保每個人只能讀寫自己的存檔，所以 anon key 放在公開的程式碼裡也沒關係。

## 3. 讓信件寄出「驗證碼」

預設信件只有登入連結，遊戲要的是數字驗證碼：

1. **Authentication → Emails（Email Templates）**。
2. 編輯 **Magic Link** 與 **Confirm signup** 兩個範本，把內文換成（或加入）：

   ```html
   <h2>刷題地牢登入驗證碼</h2>
   <p>你的驗證碼是：<b style="font-size:24px">{{ .Token }}</b></p>
   <p>10 分鐘內有效。如果不是你本人操作，請忽略這封信。</p>
   ```

3. **Authentication → Sign In / Providers → Email**：確認 Email 已啟用。

> 免費方案內建寄信服務每小時只能寄少量信件，自己用足夠；如果要給很多人用，到 **Authentication → SMTP** 接自己的寄信服務（例如 Resend、Gmail SMTP）。

## 4. 填入遊戲

二選一：

- **推薦**：把 URL 與 key 填進 `js/cloud-config.js`，所有裝置打開就能直接登入。
- 或在遊戲裡 **設定與存檔 → ☁ 雲端同步** 直接貼上（只存在那台瀏覽器，每台裝置都要貼一次）。

## 使用方式

- 頂部的 ☁ 按鈕：灰色＝未登入、綠色 ☁✓＝已同步、☁…＝同步中、紅色 ☁!＝失敗（滑鼠移上去看原因，網路恢復後會自動重試）。
- 開啟遊戲時自動下載雲端較新的進度；作答後約 30 秒內、或切換到其他分頁時自動上傳。
- 第一次在已有進度的裝置登入、而雲端也已有存檔時，會詢問要用哪一份；另一份留在本機的「衝突備份」。
- 兩台裝置離線時都玩過：以較晚修改的為準，另一份留在本機的「衝突備份」（最多 3 份），可在 ☁ 面板還原。
- 同步內容與「匯出存檔」相同（角色、作答紀錄、錯題、遠征、番茄鐘、學習模式、彈珠刷題）。導入素材（📥）、音量與計算機紀錄不同步。

## 注意

- Supabase 免費專案連續 7 天沒有任何請求會被暫停，到 Supabase 網站按 Restore 即可恢復，資料不會消失。
- 每個題庫專案（`content/` 的 meta id）分開存，同一個帳號可以同步多套題庫框架。
