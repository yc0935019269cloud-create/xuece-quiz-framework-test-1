# 07 審查、修正、連結

> 7-A：請「另一個」AI 審查已產出的課程或題目（最推薦：用不同的 AI 交叉檢查，錯誤會少很多）。
> 7-B：導入時出現「無法辨識」「JSON 格式錯誤」或很多提醒時，把訊息和檔案交給 AI 修。
> 7-C：把「題庫 ⇄ 學習課程」連結做嚴謹（宣告單元 banks、每課 teaches，實戰才不會抽到沒教過的題）。
> 7-D：在這個框架資料夾裡用 Claude Code 一次處理。
> 7-E：覆蓋審計——檢查「教材的深度有沒有追上題目」，不夠深的地方補上教材；題目維持原本難度（建議每個新單元做完都跑一次）。
> 要審查的檔案：導入頁的「下載」可以把已導入的內容匯出成一個檔。

## 7-A 品質審查（交叉檢查）

````text
你是嚴格的學科審稿委員。我上傳的是由另一個 AI 產生的教學內容（學習遊戲的 JSON：題庫 xd-bank、學習課程 xd-learn，或整包 xd-bundle），可能還附上原始素材。請逐項審查並直接修正。

# 審查項目
1. 正確性（最重要）：
   - 每一題：自己獨立解一遍，確認答案正確、唯一；多選題逐一確認每個選項。
   - 數字、公式、單位、正負號、常數、年代、人名、構造名稱（中英文）、神經血管支配。
   - 詳解的推理是否正確、與答案一致；誘答分析是否正確。
   - 有原始素材時：內容是否與素材一致；有沒有素材沒有、而且不是公認基本事實的內容（可能是捏造）。
2. 完整性（有原始素材時）：素材中的每個小節、表格、圖、例題、數據、例外是否都有被涵蓋；列出遺漏並補上。
   - 有題庫與課程時：題目（含選項、詳解）用到的符號、公式、數值、名詞，課程有沒有教；教材沒教到或教得比題目淺的列出來，補教材、不要降低題目難度（細部作法見 7-E）。
3. 清楚度：題幹有沒有歧義、條件不足；概念卡是否先白話後專業、專有名詞有沒有解釋；hint 有沒有直接洩漏答案。
4. 教學品質：誘答選項是否合理、答案字母是否分散、題目難度分布是否恰當、課程節奏（intro → (card → check) × N → example → practice → recap）是否完整。
5. 格式：JSON 合法（沒有註解、結尾逗號）；題庫 answer 是字母、tf 是 true/false、fill 有 accept；圖解座標在 0～100 或 null；沒有 LaTeX。

# 修正方式
- 能確定的錯誤直接修正。
- 答案有爭議、素材本身可能有錯、你不確定的：不要改，列進清單請老師確認。
- 不要改動任何 id（set.id、題號 n、單元 id、lesson id），不要刪除題目或課（有嚴重問題的在清單中說明）。
- 維持原本的 JSON 結構與格式。

# 輸出
1. 【審查報告】表格：位置（題號或「單元／課／第幾步」）｜問題類型｜原本內容｜修正後｜理由。
2. 【請老師確認】清單。
3. 修正後的完整 JSON：你能建立檔案就提供下載（檔名與原檔相同）；不能就先寫「檔名：原檔名」，再用 ```json 程式碼區塊輸出完整內容（合法 JSON）。
太長一次輸出不完時，在完整一題或一課後停止，寫「【未完，請回覆「繼續」】」，之後輸出剩下部分（相同 id，會自動合併）。
````

## 7-B 修正格式錯誤

```text
我把檔案導入學習遊戲時，出現下面的錯誤或提醒。請修正檔案，規則：
- 「JSON 格式錯誤」：找出並修正語法（常見：少逗號、多逗號、引號沒關、字串裡有未跳脫的雙引號、字串裡直接換行、用了 // 註解、中文引號 “ ” 當成 JSON 引號）。多行文字改成字串陣列。
- 「看不出是題庫還是學習單元」：題庫要有 questions 陣列（外層可用 {"schema":"xd-bank/1","set":{...},"questions":[...]}），學習課程要有 lessons 陣列（{"schema":"xd-learn/1",...,"lessons":[...]}），多份內容可包成 {"schema":"xd-bundle/1","subjects":[],"sets":[],"packs":[]}。
- 「看不懂答案」：題庫的單選 answer 寫一個字母（"B"），多選寫字母串（"ACE"），是非寫 true/false，填答寫答案並用 accept 陣列列出其他寫法。
- 「沒有詳解」：補上詳解（考點 → 解題過程 → 選項分析）。
- 「找不到圖片」：確認 img 路徑的檔名與實際圖片檔名一致（英數檔名，不要空格）；列出需要的圖片清單。
- 「圖解有標記沒有座標」：可以不用修（學生會在遊戲中自己點位置）；你能看到圖時可補上 x、y（圖片寬高百分比）。
- 不要改動任何 id、題號；沒被點名的內容不要改寫。
輸出修正後的完整檔案（合法 JSON），能建立檔案就提供下載，不能就先寫「檔名：…」再用 ```json 程式碼區塊輸出。

【錯誤訊息】
（貼上導入頁顯示的「無法辨識」「提醒」內容）
```

## 7-C 題庫 ⇄ 課程：嚴謹連結

````text
我上傳兩個檔案：①題庫（xd-bank，或 xd-bundle 裡的 sets）②學習課程（xd-learn，或 xd-bundle 裡的 packs）。請把「題庫 ⇄ 課程」的連結做嚴謹。**不要刪題、不要改題目的答案與 id；不要為了讓連結通過而把沒教的東西寫成教過。**

# 背景
遊戲的「實戰」會從題庫抽題。如果只靠關鍵字，會抽到別的單元、或後面幾課才教的題目，學生就會被問到沒學過的東西。所以連結要明確宣告：
- 單元欄位 "banks": ["題本 set.id", …] ＝這個單元負責的題本；"prior": [...] ＝前面單元可複習的題本。
- 每一課欄位 "teaches": ["標籤詞", …] ＝這一課教了哪些題庫標籤（tags）。一題要被抽到，它所有的 tags 都必須已在「這一課或更早的課」教過。

# 做法
1. 單元加上 banks（必要時 prior）。題本 id 必須是題庫真的存在的 set.id。
2. 逐題檢查：這題用到的每個觀念、符號、公式、數值，是否在「這題該被連到的那一課（含更早的課）」教過？
   - 教過：把這題的標籤詞寫進那一課的 teaches（課程用字和標籤不同時，也在概念卡補上對照說法）。
   - 沒教過：不要寫進 teaches；列進【缺口清單】，並依 7-E 替那一課補寫概念卡與檢核（補完才可以寫進 teaches）。
3. 每個 practice：pick.match 改成該課 teaches 裡的詞（要和題庫標籤一致，不要用各單元都會出現的籠統詞）；也可以用 qids 指定 1～3 題最相關的題目（id 格式「題本id-題號」，只能用真的存在的題；非選題盡量不要選；找不到夠相關的就讓 qids 保持 []）。
4. 檢查有沒有「孤兒題」（沒有任何一課的實戰連得到）和「抽題池太小」（符合條件的題少於 pick.n），調整 teaches 或 match。
5. 其他內容不要改動。

# 輸出
1. 【連結表】：課 → teaches → 對應的題號 → 備註。
2. 【缺口清單】：題號｜缺的觀念／符號｜應該補在哪一課。
3. 【孤兒題與抽題池】：哪些題連不到、哪些課的抽題池太小，以及你的處理。
4. 修改後的完整課程 JSON（能建立檔案就提供下載，不能就先寫「檔名：…」再用 ```json 區塊輸出）。
````

## 7-E 覆蓋審計：教材的深度追上題目了嗎？

````text
你是嚴格的教學審查員。我上傳「學習課程」（xd-learn，或 xd-bundle 裡的 packs）和它對應的「題庫」（xd-bank，或 sets）。目標：**檢查教材的深度有沒有追上題目，不夠深的地方補上教材**。題目要保持原本的難度：不要改題目、答案與任何 id，也不要建議刪題或簡化。

# 步驟
1. **建立【題庫詞彙表】**（V1、V2…）：把題庫所有題目（題幹、選項、詳解、題組文字）用到的下列東西逐條列出，標明出現在哪幾題：
   - 標籤與專有名詞（中英文）；
   - 符號與縮寫（例如 Pe、Pv、d̄、n₂、JCC、MPMVA）——特別注意：題目用了符號卻沒有人定義它，是最常見的缺口；
   - 公式、常數、數值與門檻（例如 r = 337.5/K、156 mmHg、6.00 D）；
   - 流程、分類、比較表、例外與條件。
2. **逐條對照課程**，給每一條一個狀態：
   - 已教：寫出在哪一課第幾步（卡片標題）；
   - 教得太淺：課程只提到名稱，沒有定義、公式、數值或例子，不足以答對題目；
   - 沒教：課程完全沒有；
   - 順序太晚：題目連得到的那一課，這個觀念要到後面的課才教。
3. **解題深度檢查**：挑出題庫最難的 10 題（level 3、多選、題組、非選、多步驟計算、臨床案例）。逐題確認課程有沒有教到「解這題需要的方法」：公式與適用條件、完整的多步驟示範（example）、常見陷阱、易混淆對照、情境應用。只教了定義、沒教過解法或沒示範過的，視為「教得太淺」。
4. **抽題範圍檢查**：列出每個 practice 的 pick.match 實際會抽到哪些題；有沒有抽到別的單元、或後面課才教的題。
5. **補教材**：對「教得太淺／沒教／順序太晚」的每一條，以及第 3 步發現的解法缺口：
   - 在適當的課新增概念卡（一張卡一個觀念；定義→白話→為什麼→怎麼用→帶數字的例子→易錯），後面緊接 1～2 題 check；或擴充既有卡片（卡片仍在 900 字內）；
   - 符號第一次出現就說明意義與單位；
   - 最難題對應的解法，用 example 逐步示範（已知 → 判斷 → 列式 → 代入 → 檢查），再接一題同型但換數字的 check；
   - 數值、公式、正負號全部重算。
6. **補連結**：單元寫 banks（必要時 prior）；每課寫 teaches（只寫該課真的教了的標籤）；pick.match 改用 teaches 裡的詞。
7. 你不確定的（素材沒有、你也不能確認是公認事實）不要寫，列進【需要確認】。

# 輸出
1. 【題庫詞彙表覆蓋表】：V 編號｜詞／符號／公式｜出現題號｜狀態｜課程位置。
2. 【缺口與補強】：每個缺口 → 你補在哪一課哪一步（標題）。
3. 【最難題的解題深度檢查】：題號｜需要的解法｜課程有沒有教｜你補在哪。
4. 【抽題範圍檢查】。
5. 【需要確認】。
5. 修改後的完整課程 JSON（只新增或擴充內容；原有的 id、順序、其他內容不變）：能建立檔案就提供下載，不能就先寫「檔名：原檔名」再用 ```json 區塊輸出。內容太長時，在完整一課後停止並寫「【未完，請回覆「繼續」】」。
````
