# 07 審查、修正、連結

> 7-A：請「另一個」AI 審查已產出的課程或題目（最推薦：用不同的 AI 交叉檢查，錯誤會少很多）。
> 7-B：導入時出現「無法辨識」「JSON 格式錯誤」或很多提醒時，把訊息和檔案交給 AI 修。
> 7-C：讓學習課程的實戰關卡用到你題庫裡的題目。
> 7-D：在這個框架資料夾裡用 Claude Code 一次處理。
> 要審查的檔案：導入頁的「下載」可以把已導入的內容匯出成一個檔。

## 7-A 品質審查（交叉檢查）

````text
你是嚴格的學科審稿委員。我上傳的是由另一個 AI 產生的教學內容（學習遊戲的 JSON：題庫 xd-bank、學習課程 xd-learn，或整包 xd-bundle），可能還附上原始素材。請逐項審查並直接修正。

# 審查項目
1. 正確性（最重要）：
   - 每一題：自己獨立解一遍，確認答案正確、唯一；多選題逐一確認每個選項。
   - 數字、公式、單位、正負號、常數、年代、人名、構造名稱（中英文）、神經血管支配。
   - 詳解的推理是否正確、與答案一致；誘答分析是否正確。
   - 有原始素材時：內容是否與素材一致；有沒有素材沒有、而且不是公認基本事實的內容（可能是捏造）。
2. 完整性（有原始素材時）：素材中的每個小節、表格、圖、例題、數據、例外是否都有被涵蓋；列出遺漏並補上。
3. 清楚度：題幹有沒有歧義、條件不足；概念卡是否先白話後專業、專有名詞有沒有解釋；hint 有沒有直接洩漏答案。
4. 教學品質：誘答選項是否合理、答案字母是否分散、題目難度分布是否恰當、課程節奏（intro → (card → check) × N → example → practice → recap）是否完整。
5. 格式：JSON 合法（沒有註解、結尾逗號）；題庫 answer 是字母、tf 是 true/false、fill 有 accept；圖解座標在 0～100 或 null；沒有 LaTeX。

# 修正方式
- 能確定的錯誤直接修正。
- 答案有爭議、素材本身可能有錯、你不確定的：不要改，列進清單請老師確認。
- 不要改動任何 id（set.id、題號 n、單元 id、lesson id），不要刪除題目或課（有嚴重問題的在清單中說明）。
- 維持原本的 JSON 結構與格式。

# 輸出
1. 【審查報告】表格：位置（題號或「單元／課／第幾步」）｜問題類型｜原本內容｜修正後｜理由。
2. 【請老師確認】清單。
3. 修正後的完整 JSON：你能建立檔案就提供下載（檔名與原檔相同）；不能就先寫「檔名：原檔名」，再用 ```json 程式碼區塊輸出完整內容（合法 JSON）。
太長一次輸出不完時，在完整一題或一課後停止，寫「【未完，請回覆「繼續」】」，之後輸出剩下部分（相同 id，會自動合併）。
````

## 7-B 修正格式錯誤

```text
我把檔案導入學習遊戲時，出現下面的錯誤或提醒。請修正檔案，規則：
- 「JSON 格式錯誤」：找出並修正語法（常見：少逗號、多逗號、引號沒關、字串裡有未跳脫的雙引號、字串裡直接換行、用了 // 註解、中文引號 “ ” 當成 JSON 引號）。多行文字改成字串陣列。
- 「看不出是題庫還是學習單元」：題庫要有 questions 陣列（外層可用 {"schema":"xd-bank/1","set":{...},"questions":[...]}），學習課程要有 lessons 陣列（{"schema":"xd-learn/1",...,"lessons":[...]}），多份內容可包成 {"schema":"xd-bundle/1","subjects":[],"sets":[],"packs":[]}。
- 「看不懂答案」：題庫的單選 answer 寫一個字母（"B"），多選寫字母串（"ACE"），是非寫 true/false，填答寫答案並用 accept 陣列列出其他寫法。
- 「沒有詳解」：補上詳解（考點 → 解題過程 → 選項分析）。
- 「找不到圖片」：確認 img 路徑的檔名與實際圖片檔名一致（英數檔名，不要空格）；列出需要的圖片清單。
- 「圖解有標記沒有座標」：可以不用修（學生會在遊戲中自己點位置）；你能看到圖時可補上 x、y（圖片寬高百分比）。
- 不要改動任何 id、題號；沒被點名的內容不要改寫。
輸出修正後的完整檔案（合法 JSON），能建立檔案就提供下載，不能就先寫「檔名：…」再用 ```json 程式碼區塊輸出。

【錯誤訊息】
（貼上導入頁顯示的「無法辨識」「提醒」內容）
```

## 7-C 讓課程的實戰用到題庫題目

```text
我上傳兩個檔案：①題庫（xd-bank 或 xd-bundle 裡的 sets）②學習課程（xd-learn 或 xd-bundle 裡的 packs）。
請替課程中每一個 "type": "practice" 步驟挑選 1～3 題最相關的題庫題目，把題目 id 填進它的 "qids"。

- 題目 id 的格式是「題本id-題號」，例如 set.id 為 "physopt-ch2-gen"、題號 n 為 7，id 就是 "physopt-ch2-gen-7"。只能用真的存在的題目。
- 題目考的觀念必須落在「這一課」教過的範圍內，不要用後面才教的觀念；同一課盡量挑不同題型、由淺到深。
- 非選（open）題盡量不要選；找不到夠相關的題目就讓 qids 保持 []。
- 順便檢查 pick.match 關鍵字：改成題庫 tags 裡實際出現的詞，讓自動抽題抽得到。
- 其他內容不要改動。
輸出：①表格（課 → 挑了哪些題目 id → 對應觀念 → 理由）②修改後的完整課程 JSON（能建立檔案就提供下載，不能就先寫「檔名：…」再用 ```json 區塊輸出）。
```

## 7-D 交給 Claude Code（在這個框架資料夾開的 Claude Code 對話裡用）

```text
我有新的內容要放進這個刷題遊戲框架（檔案路徑或內容在下面）。請：
1. 題庫放 content/bank/<科目id>/，學習課程放 content/learn/<科目id>/，整包（xd-bundle）可以直接放 content/；圖片放 img/ 對應資料夾；科目不存在就加到 content/project.json（theme 依科目性質選）。
2. 執行 python tools/build.py，有錯誤或節奏警告就直接修到乾淨。
3. 抽查答案：數理題實際重算；答案和詳解結論不一致、或詳解寫「⚠ 答案存疑」的，列給我看，不要自己改答案。
4. 沒有詳解的題目，依 docs/prompts/03_既有題目補詳解.md 的標準補上。
5. 課程 practice 的 qids 是空的，就用 python tools/build.py --index 產生的索引挑 1～3 題相關題目，列出理由。
6. 在預覽裡實際開一次：每種題型各玩一題、跑一課學習模式（含圖解與互動），確認 console 沒有錯誤。

（貼上檔案路徑或內容）
```
