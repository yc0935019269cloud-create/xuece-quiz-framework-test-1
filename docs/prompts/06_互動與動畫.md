# 06 互動與動畫

> 光路與成像、透鏡度數、調節、波動、電路、函數圖形、統計分布、生理流程（神經傳導、心動週期、房水循環）……這類「會動、會變」的觀念，用互動模擬比文字好懂得多。
> 用這個提示詞做出來的互動內容，會變成學習模式裡的「🎮 互動」步驟（放在沙盒裡執行，離線可用）。
> 已經有課程時，請 AI 產出一個只有這幾課的新單元，或把 interactive 步驟插入原本的課程 JSON。

## 6-A 做互動模擬

````text
你是擅長做教學互動模擬的前端工程師，也是這個學科的老師。請為我指定的觀念做「互動模擬」，放進學習遊戲的課程中。

# 先判斷：需要互動嗎？
只有在「操作與觀察」能明顯幫助理解時才做：參數改變會造成結果變化（度數、物距、角度、頻率、濃度…）、過程有先後或動態（光線行進、傳導、循環、細胞分裂）、圖形變換。只是靜態知識（名詞、分類）不要做互動，改用概念卡或圖解。

# 互動內容的技術規則（必須全部遵守）
1. 一份完整、獨立的 HTML 文件（<!doctype html> 開頭），只用原生 HTML、CSS、JavaScript；可用 SVG 或 canvas。
2. 不可以載入任何外部資源：不用 CDN、外部字型、fetch、XMLHttpRequest、外部圖片網址。需要圖就用 SVG 或 canvas 畫。
3. 不可以使用 alert、confirm、prompt、localStorage、sessionStorage、cookie、表單送出、開新視窗。
4. 版面：寬度 100%（會放在約 700～1000 px 寬的框內，手機約 360 px 也要能用），高度不超過 560 px；文字至少 14 px；背景淺色（#fbf7ec）、文字深色；顏色對比清楚，重要元素不要只靠顏色區分。
5. 所有標示、按鈕、說明用繁體中文；數值要有單位並即時顯示。
6. 控制項：滑桿（附目前數值）、按鈕（播放、暫停、重設、逐步），必要時可拖曳。動畫用 requestAnimationFrame，要能暫停。
7. 畫面上方或下方固定顯示一行「觀察重點」，並在特定情況顯示提示（例如「像在焦點以內變成正立虛像」）。
8. 物理、數學、生理必須正確：使用正確公式與正負號慣例，並在畫面角落註明使用的公式與慣例（例如「薄透鏡公式 1/v − 1/u = 1/f，光由左向右」）；邊界情況（除以零、無限遠）要處理，不可出現 NaN。
9. 程式碼精簡、可讀，總長度盡量在 15 KB 以內。

# 課程安排
每個互動放在一課中，前後照這個節奏：
card（先說明觀念與公式）→ interactive（task 寫一個具體任務，例如「調整鏡片度數，讓成像剛好落在視網膜上」）→ check（1～2 題驗收：「剛才觀察到…時會怎樣」）→ 需要時再一組 → example → practice → recap。
card 的寫法：一句話定義 → 白話說明 → 原理或公式（每個符號與單位）→ 數值例子 → 易錯點。

# 各類主題的建議做法
- 幾何光學／生理光學：光學桌（光軸、透鏡或眼球模型、可拖曳物體、主光線三條）；即時顯示物距、像距、放大率、像的性質；近視／遠視眼加上矯正鏡片度數滑桿；調節與近點、遠點；稜鏡偏折。
- 視光學：散光的兩條焦線與最小模糊圈（柱鏡軸度滑桿）；驗光流程的逐步模擬；視力表與視角的關係。
- 物理：力與運動圖（x-t、v-t 同步）、波的疊加、電路（改電阻看電流）、斜面與摩擦。
- 數學：函數圖形參數滑桿（a、h、k）、三角函數與單位圓、機率模擬（擲骰次數滑桿）、向量加法。
- 化學：勒沙特列原理（改濃度、溫度、壓力看平衡移動）、滴定曲線。
- 生物／生理：動作電位時間軸、心動週期壓力容積、房水生成與排出路徑動畫、細胞分裂階段逐步播放。

- html 可以寫成字串陣列（一個元素一行），也可以是一個字串；字串內的雙引號要寫成 \"，反斜線寫成 \\。

- practice.checks 可以是空陣列，但至少要有 pick 或 checks 其中一種。
- JSON 必須合法（不能有註解、結尾逗號）；不能用 LaTeX（用 Unicode：x²、θ、≤、Δ）。
